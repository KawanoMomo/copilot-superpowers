# じゃんけんアプリ設計（Web版）

日付: 2026-03-26
タイトル: Webブラウザで動く一人用じゃんけんアプリ

## 目的
- 簡単なWeb UIでユーザーが「グー／チョキ／パー」を入力し、CPUと勝負できる
- 勝敗判定を行い、ユーザー勝ち・CPU勝ち・引き分けのスコアを表示
- リセット可能
- モバイルのタッチ操作にも対応するレスポンシブなUI

## 範囲
### 優先実装
- プレイヤー vs CPU（ランダム）
- 1ラウンド勝敗判定
- 累計スコア表示（player/cpu/draw）
- 最新の結果表示領域
- リセットボタン
- 状態の分離（ロジックとUI）

### 除外（本フェーズ外）
- LAN/オンライン対戦
- AIの難易度調整（統計学習）
- ローカルストレージ永続化
- アニメーション・音声（後フェーズで可）

## 推奨アプローチ
- バニラHTML/CSS/JavaScript（依存なし、即実装、最小限）

## コンポーネント
- `index.html`
  - 選択ボタン: グー/チョキ/パー
  - ステータス表示: 選択中の手、CPUの手、勝敗
  - スコアボード: player/cpu/draw
  - リセットボタン

- `styles.css`
  - レスポンシブ（モバイル優先）
  - ボタンと状態の視認性
  - アクセシビリティ（フォーカス、コントラスト）を意識

- `app.js`
  - 定数: `MOVES = ['rock', 'paper', 'scissors']`
  - 状態管理: `playerScore`, `cpuScore`, `drawCount`, `round` など
  - 関数:
    - `getCpuMove()` -> ランダムに手を決定
    - `decideWinner(playerMove, cpuMove)` -> 'win'/'lose'/'draw'
    - `updateScore(result)` -> スコアを更新
    - `render()` -> DOMに反映
    - `resetGame()` -> 状態初期化
  - イベント:
    - ボタンクリック -> ゲームラウンド実行
    - リセットボタン -> `resetGame()`

## データフロー
1. ユーザーが手を選択
2. `getCpuMove()` でCPU手を決定
3. `decideWinner()` で勝敗判定
4. `updateScore()` で状態更新
5. `render()` でUI更新
6. 追加: ラウンド制限や連勝表示を容易に対応できる設計

## エッジケース / 例外処理
- 無効入力不可能なUI設計（buttonで固定）
- コンテンツDOMが取得できない場合はコンソールエラー
- 連打対策: ラウンド処理中はボタン無効化（必要に応じて）

## テスト戦略
### 1) 単体テスト
- `decideWinner()` 実装が9ケースすべてで正しく勝敗を返す
- `getCpuMove()` 3種類のどれかを返し、分布は乱数なこと
- `updateScore()` のスコア計算

### 2) 結合テスト（DOM）
- ボタンクリック -> 結果が表示される
- スコアが増減する
- リセットですべてゼロに戻る

### 3) E2E（可能）
- Cypress / Playwright で「グーを選んで勝敗出力」
